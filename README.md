# Сочетания вкусов

Личный справочник по кальянным миксам: https://avemepls95.github.io/food-pairing/

Четыре независимые страницы:

- **Граф** (`#/`) - сочетаемость вкусов из таблиц. Фильтр по силе сочетания, поиск продукта, два режима показа связей.
- **Полка** (`#/shelf`) - свои банки табака: бренд, название и вкусы из справочника. Галочка заводит банку на один вкус.
- **Подбор** (`#/picks`) - миксы из того, что стоит на полке, с долями и объяснением. Число банок задаёте вы или подбор.
- **Миксы** (`#/mixes`) - свой список миксов с оценкой и категориями «попробовал» и «в планах».

Бэкенда нет. Данные графа лежат в репозитории, полка и миксы - в localStorage браузера, с выгрузкой и загрузкой файла.

## Разработка

```bash
npm install
npm start
```

Сборка: `npm run build`, результат в `dist/food-pairing-hookah-frontend/browser`.
Тесты: `npm test` (vitest, чистые модули без Angular).

## Данные графа

- `public/data/tables.json` - распознанные таблицы как есть: заголовок, колонки-категории и ячейки `[текст, цвет]`.
  Цвет: `R` сильнее всего, дальше `O`, `G`, `B`, а `P` - минимальная сочетаемость.
- `public/data/products.json` - справочник продуктов: каноническое имя, категория и варианты написания из таблиц.

Граф собирается в браузере (`Core/graph/graph-data.ts`): названия приводятся к каноническим через справочник,
пара продуктов даёт одну связь с самым сильным уровнем из всех таблиц. Бледный уровень остаётся только у пар,
бледных во всех таблицах; на графе такие связи не показываются, а подбор их не предлагает. Название из цветной
ячейки, которого нет в справочнике, попадёт в консоль и станет отдельным узлом. Из бледной ячейки такое название
пропускается: там копятся опечатки и сокращения.

Чтобы добавить таблицу: дописать её в `tables.json`, а недостающие названия - в `products.json`.

## Подбор миксов

Балл микса считается по парам вкусов из разных банок: среднее силы пар, поправка на композицию (есть ли основа,
один ли акцент, насколько разные категории) и поправка на личные оценки попробованных миксов. Проверенные показывают миксы, где все пары зелёные и выше, сбалансированные
допускают синие, смелые собраны из миксов с парой, которой нет в таблицах. Если под выбранный режим миксов
не набралось, подбор пробует следующий и пишет об этом в выдаче. Микс можно отклонить, и тогда этот набор
вкусов больше не предлагается; отклонённые считаются под выдачей и возвращаются одной кнопкой. Алгоритм лежит в `Components/picks/recommender.ts`, на него есть тесты.

## Хранение

Ключ `food-pairing.library` держит полку и миксы вместе. Старый ключ `food-pairing.mixes` читается при первом
запуске: вкусы оттуда сопоставляются со справочником, несопоставленный текст остаётся как есть.
Файл копии содержит обе части; файл старого формата заменяет только миксы.

## Публикация

Пуш в `main` запускает `.github/workflows/pages.yml`: тесты, сборка с `--base-href /food-pairing/` и публикация
на GitHub Pages.
