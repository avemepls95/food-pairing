# Группы вкусов в подборе

## Зачем

На полке стоит банка «Груша», а справочник знает грушу, зелёную грушу и жёлтую грушу тремя разными вкусами.
Подбор считает их разными тоже: миксы, которые таблицы описали через зелёную грушу, до банки не доходят,
а «сыр и зелёная груша» с «сыром и жёлтой грушей» занимают два места в выдаче под один и тот же микс.
Пользователь считает все три груши своей грушей. Тот же случай у яблока, винограда, вишни, смородины,
а по смыслу ещё у сыра с горгонзолой.

Группа это набор вкусов справочника, который подбор считает одним вкусом.

## Что входит

- Группы в библиотеке пользователя: название и список вкусов справочника.
- Окно групп на странице подбора с двумя вкладками: подсказки с галочками и свои группы с правкой.
- Подсказки двух видов: по общему слову в названии и по смыслу из списка в коде.
- Подбор считает вкусы группы одним вкусом: пары, балл, фильтр аромата, журнал, скрытые наборы, личные оценки.
- Группы попадают в файл выгрузки и читаются из него.

## Что не входит

- Граф. Страница графа и `buildGraph` остаются как есть, узлы не сливаются.
- Полка и журнал миксов. Банка хранит выбранные вкусы, карточка микса показывает название банки.
- Правка справочника из интерфейса.
- Общие группы для всех: список свой у каждого, как полка и миксы.

## Чего нельзя допустить

- Группа меняет справочник или граф.
- Группа появляется без подтверждения. Подсказка ждёт галочки, даже самая очевидная.
- Один вкус лежит в двух группах.
- Полка, миксы и скрытые наборы теряются при переходе хранилища на версию 3.
- Пользователь видит название группы и не может вспомнить её состав.

## Данные

### Модель

```ts
/** Вкусы справочника, которые подбор считает одним вкусом */
export interface FlavorGroup {
  id: string;
  /** Имя группы в выдаче */
  name: string;
  /** Вкусы справочника, минимум два; первый задаёт категорию */
  flavors: string[];
}
```

Имя группы служит ключом в картах подбора, поэтому одно имя всегда означает одно и то же. Имя не совпадает
ни с именем другой группы, ни со вкусом справочника вне этой группы. Группа «груша» из жёлтой и зелёной груши
при свободной груше не сохраняется, а та же группа вместе с самой грушей сохраняется. Имена сравниваются
через `toKey`, тем же сравнением, что сводит написания таблиц к одному имени.

Имя `FlavorGroup` сейчас занято списком вкусов одной категории для компонента выбора (`graph-data.ts`).
Он переименовывается в `CategoryGroup`: 9 файлов, механическая замена.

### Хранение

`Library` получает поле `groups`, `STORAGE_VERSION` становится 3. Ключ `food-pairing.library` и формат
остальных полей не меняются. Файл выгрузки содержит `{ version: 3, jars, mixes, rejected, groups }`.

Загрузка файла:

| Версия файла | Что заменяется |
|---|---|
| 3 | полка, миксы, скрытые наборы, группы |
| 2 | полка, миксы, скрытые наборы; группы остаются на месте |
| 1 | только миксы, как сейчас |

Признак `mixesOnly` сейчас вычисляется как `version < STORAGE_VERSION` и после поднятия версии соврал бы
про файл версии 2. Он становится `version < 2`.

Разбор группы работает по правилам банки: `id` выдаётся заново при повторе, имя и вкусы обрезаются,
запись без имени или меньше чем с двумя вкусами пропускается и попадает в счётчик `skipped`. Туда же уходит
запись с именем, которое уже занято другой группой или свободным вкусом справочника. Вкус, встреченный
в двух группах файла, остаётся в первой.

Вкус, пропавший из справочника, в группе сохраняется и в подборе не участвует. Группа, где известных вкусов
осталось меньше двух, в подборе не строится, и единственный известный вкус работает сам по себе.

## Подсказки

### Общее слово

Внутри одной категории собираются вкусы с совпадающим последним словом названия. Односложное имя, равное
этому слову, входит в ту же подсказку. На справочнике из 190 имён правило даёт 15 подсказок:

| Категория | Подсказка |
|---|---|
| Гастро | хлеб, ржаной хлеб |
| Напитки | белое сухое вино, красное сухое вино |
| Напитки | виски, односолодовый виски |
| Напитки | имбирное пиво, темное пиво |
| Напитки | ром, белый ром, темный ром |
| Напитки | жасминовый чай, зеленый чай, черный чай, копченый черный чай |
| Орехи | грецкий орех, кедровый орех, лесной орех, мускатный орех |
| Специи | горный перец, душистый перец, розовый перец, черный перец |
| Травы | мята, перечная мята |
| Фрукты | груша, желтая груша, зеленая груша |
| Фрукты | яблоко, зеленое яблоко, красное яблоко |
| Цитрус | апельсин, красный апельсин |
| Ягоды | виноград, светлый виноград, темный виноград |
| Ягоды | кислая вишня, сладкая вишня |
| Ягоды | красная смородина, черная смородина |

Категория в правиле отсекает «цветы апельсина» от апельсина, «сливочный сыр» от сыра и «огуречный сок»
от грейпфрутового.

Смысла правило не понимает: мускатный орех попадает к грецкому, жасминовый чай к чёрному, белое вино
к красному. Поэтому галочки сняты по умолчанию и каждая подсказка ждёт подтверждения.
Название подсказки это общее слово.

### Список по смыслу

Константа рядом с правилом, собрана руками по справочнику:

| Подсказка | Имя |
|---|---|
| сыр, горгонзола, рокфор, чеддер | сыр |
| лосось, красная рыба | лосось |
| говядина, стейк | говядина |
| какао, темный шоколад | шоколад |
| клубника, земляника | клубника |
| мандарин, танжерин | мандарин |
| грейпфрут, грейпфрутовый сок | грейпфрут |
| персик, нектарин | персик |
| огурец, огуречный сок | огурец |
| зеленый чай, сенча, матча | зеленый чай |
| коньяк, бренди | коньяк |
| текила, мескаль | текила |
| виски, односолодовый виски, бурбон | виски |
| сосна, пихта | хвоя |

Подсказка поглощает ту, чьи вкусы целиком в неё входят. Виски из правила по слову входит в виски с бурбоном
из списка по смыслу, и остаётся одна подсказка из трёх вкусов с именем из списка. Подсказки, которые просто
пересекаются, остаются отдельными: чай из правила по слову и зелёный чай с сенчой и матчей делят один вкус,
а слияние спрятало бы чёрный и жасминовый чай под именем зелёного. Имя из списка по смыслу может не быть
вкусом справочника («хвоя»).

Подсказка пропадает из списка, как только занят хотя бы один её вкус или её имя. Остаток пользователь
добирает руками на второй вкладке.

## Алгоритм

Подбор получает группы один раз на расчёт и строит две карты:

```
имя(вкус)   = название группы, если вкус в ней, иначе сам вкус
вкусы(имя)  = вкусы группы, если имя это группа, иначе сам вкус
```

Банки подменяются на эффективные: тот же `id`, вкусы прогнаны через `имя()` и дедуплицированы.
Перебор, гейты, доли и балл работают с ними без изменений, поэтому банка с грушей и зелёной грушей
даёт один вкус. Правило «банки с общим вкусом вместе не предлагаем» начинает работать и для банок,
чьи вкусы попали в одну группу.

Контекст оценки отвечает про группу через её вкусы:

| Вопрос | Ответ для группы |
|---|---|
| `level(a, b)` | максимальный уровень среди пар вкусов `a` и `b` |
| `sides(a, b)` | число сторон у пары, давшей этот уровень |
| `categoryOf` | самая частая категория среди вкусов, при равенстве категория первого |
| `knows` | да, карты строятся только из вкусов справочника |
| `hasTable` | своя таблица есть хотя бы у одного вкуса |

В карты попадают только известные справочнику вкусы. Группа, у которой таких вкусов осталось меньше двух,
не строится совсем, и её вкус участвует в подборе сам по себе.

Максимум берётся по уровню согласия сторон, по тому же, которым подбор оценивает любую пару сейчас.
Сыр с зелёной грушей красный, с жёлтой синий, значит пара «сыр и груша» красная. У пары двух групп
максимум берётся по всем парам их вкусов.

Журнал и скрытые наборы сравниваются по эффективным именам с обеих сторон, `flavorKey` считается от `имя()`.
Попробованный «сыр и зелёная груша» убирает из выдачи «сыр и грушу». Личные оценки (`affinities`) считаются
так же, и оценка микса с зелёной грушей переходит на группу.

Кнопка «Больше не предлагать» записывает сырые вкусы банок, взятые с полки по `jarIds` карточки. Поэтому
ключи, записанные до появления группы, продолжают работать, а переименование и удаление группы их не ломает.

Фильтр аромата проверяет вкусы группы: группа подходит, если подходит хотя бы один её вкус. Так настроения,
перечисленные вкусами («ягодное» знает кислую и сладкую вишню), продолжают работать для группы «вишня».
Список вкусов самого фильтра остаётся сырым, прямо из банок полки.

В карточке банки показываются как сейчас, именем или перечислением своих вкусов. Группы видны в чипах пар,
у чипа группы её вкусы стоят в `title`.

## Интерфейс

Кнопка «Группы вкусов» в блоке настроек подбора, под переключателем режима, с числом своих групп.
Окно это `<dialog class="dialog">` того же вида, что форма микса: шапка с заголовком и крестиком,
тело с прокруткой.

### Вкладка «Подсказки»

Открывается первой, пока у пользователя нет ни одной группы.

- Строка подсказки: галочка, имя группы, вкусы чипами.
- Внизу кнопка «Добавить N групп», неактивная без отметок.
- Над списком галочка «Выбрать все».

### Вкладка «Мои группы»

Открывается первой, когда группы есть.

- Строка группы: имя, вкусы чипами, правка и удаление.
- Кнопка «Собрать свою группу» открывает форму: поле имени и общий `app-flavor-picker` с поиском
  по категориям.
- Вкус из другой группы в выборе недоступен и подписан её именем.
- Сохранение требует имя и два вкуса, кнопка до этого неактивна. Занятое имя форма не принимает и пишет
  под полем, чем оно занято.

Закрытие окна пересчитывает выдачу. На экране ниже 780px вкладки и список прокручиваются целиком,
кнопка добавления липкая снизу, как кнопка сброса в панели фильтров.

## Проверка

Тесты vitest на чистых модулях:

- правило по слову даёт 15 подсказок на справочнике и не склеивает «цветы апельсина» с апельсином;
- виски из правила по слову поглощается подсказкой с бурбоном, имя берётся из списка по смыслу;
- чай и зелёный чай остаются двумя подсказками;
- подсказка пропадает, как только один её вкус попал в группу;
- `имя()` возвращает вкус без группы как есть;
- уровень пары с группой равен максимальному среди её вкусов, стороны берутся от победившей пары;
- категория группы берётся по большинству вкусов, при равенстве от первого;
- банка с двумя вкусами одной группы даёт один эффективный вкус;
- банки, чьи вкусы попали в одну группу, вместе не предлагаются;
- попробованный микс с зелёной грушей убирает из выдачи микс с грушей;
- скрытый набор, записанный до группы, продолжает скрывать микс после её появления и после удаления группы;
- группа с одним известным вкусом не строится, её вкус участвует сам по себе;
- имя, занятое другой группой или свободным вкусом справочника, не сохраняется;
- файл версии 2 не стирает группы, файл версии 3 их заменяет, запись без имени пропускается.

В браузере: полка с грушей и сыром, выдача до и после добавления группы, правка и удаление группы,
выгрузка и загрузка файла, окно на узком экране.

## Решения, принятые без обсуждения

- `FlavorGroup` из `graph-data.ts` переименован в `CategoryGroup`.
- Галочки подсказок сняты по умолчанию, сверху стоит «Выбрать все».
- Имя подсказки по слову это общее слово; имя подсказки по смыслу задано списком.
- Имя группы уникально среди групп и не совпадает со свободным вкусом справочника.
- Подсказка поглощается только той, в которую входит целиком.
- Подсказка пропадает целиком, как только один её вкус попал в группу.
- Категория группы это самая частая категория её вкусов, при равенстве категория первого.
- `hasTable` у группы: хотя бы один вкус со своей таблицей.
- `sides` берутся от пары, давшей уровень.
- Вкус принадлежит одной группе, в выборе чужой вкус недоступен.
- Группа из одного вкуса не сохраняется, группа с одним известным вкусом не строится.
- Скрытые наборы записываются сырыми вкусами банок.
- Список вкусов фильтра аромата остаётся сырым: настроения перечисляют вкусы справочника,
  по именам групп они бы не нашлись.
- Карточка микса показывает банки по-прежнему, группы видны в чипах пар.
- Кнопка окна стоит в настройках подбора.
- Личные оценки и журнал считаются по группам.
- Удаление группы возвращает её вкусы в подбор по отдельности, подтверждения не спрашивает.
