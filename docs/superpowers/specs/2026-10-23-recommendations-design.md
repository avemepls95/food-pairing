# Рекомендации миксов

## Зачем

Граф показывает, что с чем сочетается, но собрать микс из того, что стоит на полке, пользователь должен в голове.
Теперь он отмечает свои табаки, говорит, из скольких банок хочет микс, и получает готовые варианты с долями,
которые можно отправить в планы или в журнал попробованных.

## Что входит

- Полка: список своих банок табака с привязкой к вкусам графа.
- Подбор: вопрос о числе банок в миксе и ранжированный список миксов с объяснением, почему они предложены.
- Перенос микса из подбора в планы одним нажатием и в попробованные через форму с предзаполненным составом.
- Учёт оценок попробованных миксов при подборе.
- Отклонение микса: набор вкусов, который подбор больше не предлагает.
- Доли в чаше: алгоритм раздаёт роли и проценты, пользователь их правит.

## Что не входит

- Синхронизация между устройствами. Данные остаются в localStorage с выгрузкой и загрузкой файла.
- Добавление вкуса в полку прямо со страницы графа.
- Правка таблиц сочетаемости из интерфейса.
- Крепость, производитель чаши, время курения и прочие свойства сессии.

## Чего нельзя допустить

- Подбор молчит. Пустой список без объяснения причины недопустим: если под требования ничего не нашлось,
  требования ослабляются автоматически, а в выдаче пишется, что именно ослаблено.
- Балл выглядит точным знанием. Половина вкусов справочника своей таблицы не имеет, про их сочетания данных мало.
  Такие миксы помечаются.
- Миксы из выдачи повторяют друг друга с точностью до одной банки.
- Существующие миксы или их оценки теряются при обновлении модели данных.

## Данные

### Полка

```ts
interface Jar {
  id: string;
  brand?: string;
  /** Название на банке */
  name?: string;
  /** Вкусы графа, минимум один */
  flavors: string[];
}
```

Банка с несколькими вкусами означает готовый микс от производителя (Supernova: вишня и мята).
Вкус, отмеченный галочкой, создаёт банку с одним вкусом и пустыми бренд и название.

Вкус хранится каноническим именем из `products.json`, тем же, что служит идентификатором узла графа.
Выбирать можно только из этих имён (их 190). Если вкус сохранённой банки из справочника пропал,
банка показывает его с пометкой «нет в справочнике» и в подборе не участвует.

### Миксы

Текущая модель хранит `items: { brand?, flavor: string }[]`, где `flavor` произвольный текст.
Новая модель описывает банку и долю:

```ts
interface MixItem {
  /** Банка с полки, если микс собран из неё */
  jarId?: string;
  brand?: string;
  name?: string;
  /** Вкусы графа; текст, которого нет в справочнике, остаётся как есть */
  flavors: string[];
  /** Доля в чаше, проценты */
  share?: number;
}
```

Миграция старых записей: `flavor` приводится к каноническому имени через справочник продуктов
(`toKey` и алиасы, как в `buildGraph`), результат кладётся в `flavors`. Несопоставленный текст остаётся
в `flavors` как есть и в подборе не участвует. Поля `rating`, `category`, `name`, `id`, `updatedAt` не меняются.

### Хранение

Один ключ `food-pairing.library` версии 2 с полями `jars`, `mixes` и `rejected` (ключи отклонённых
наборов вкусов). При первом чтении, если ключа нет,
а старый `food-pairing.mixes` есть, миксы переносятся и миграция записывается. Старый ключ остаётся на месте.

Файл выгрузки содержит `{ version: 2, jars, mixes, rejected }` и заменяет эти списки целиком.
Файл версии 1 содержит только миксы: он заменяет миксы и оставляет полку на месте, о чём написано
в подтверждении замены. Записи, не прошедшие правила, пропускаются, их число показывается, как сейчас.

## Алгоритм

### Достоверность таблиц

Таблица это личный топ продукта: в 1548 колонках из 1549 ячейки отсортированы по убыванию силы.
Цвет кодирует место в списке конкретного продукта, поэтому стороны расходятся законно: манго может
стоять в пятёрке лучших у киви, а киви у манго двадцатым.

Измерено на данных:

- Пар, описанных с двух сторон: 2468. Точное совпадение 54.2% при случайном 47.4%, каппа Коэна 0.129.
- Сильных рёбер (красный или жёлтый) 702, из них 367 описаны только одной стороной.
- Форматов таблиц два: 76 штук со строчной буквы в названии категории (красных ячеек 0.8%) и 61 с заглавной
  (красных 6.6%). Шкалы у них разные.
- Правило максимума поднимает уровень у 1131 пары, 542 из них на две ступени и больше.

Отсюда два следствия. Граф остаётся на максимуме: там пользователь смотрит возможности, и щедрость уместна.
Подбор берёт уровень по согласию сторон, а при расхождении округляет вниз, ближе к слабой оценке. Число
сторон доезжает до карточки: пара, описанная одной таблицей, помечена пунктиром, а в карточке стоит
«пар с одной стороны: N». Искусственных коэффициентов уверенности нет: проверить их не на чем, поэтому
пользователь видит сырой факт.

### Вес пары вкусов

Уровень связи графа переводится в вес:

| Уровень | Вес |
|---|---|
| красный | 1.0 |
| жёлтый | 0.78 |
| зелёный | 0.55 |
| синий | 0.35 |
| нет данных | 0.12 |
| бледный (P) | 0 |

Бледные ячейки таблиц сейчас отбрасываются при сборке графа, и отсутствие связи означает одновременно
«измерили, сочетается плохо» и «никто не измерял». Поэтому `buildGraph` начинает отдавать уровень `pale`
как самый слабый, а страница графа его фильтрует.

Правило уровня остаётся тем же, что сейчас: у пары один уровень, самый сильный из всех ячеек всех таблиц.
Бледный уровень получают только пары, у которых бледные все ячейки: таких 3873 из 6470 описанных пар.
Пара, бледная в одной таблице и цветная в другой, работает по цветному уровню (таких пар 1112, и 589 из них
имеют зелёный уровень или выше). Данные противоречивы сами по себе: из 2468 пар, описанных с двух сторон,
1068 расходятся в уровне, и правило максимума уже выбрано для графа.

Имена из бледных ячеек узлов не создают. 52 названия встречаются только в бледных ячейках и в справочнике
их нет: опечатки («абруз», «крыжовние», «Черносилив»), сокращения («ж. чай», «Сл. сыр», «Одн виски») и
продукты, которых в справочнике пока нет (шафран, ревень, авокадо, джекфрут, чеснок). Бледная ячейка
с неизвестным именем пропускается, набор узлов остаётся прежним (190), в консоль такие имена не пишутся.

### Балл микса

Микс состоит из банок. Оцениваются только пары вкусов из разных банок: состав одной банки выбрал производитель,
менять его пользователь не может.

```
harmony   = среднее по связям банок, где связь это среднее веса её пар вкусов   // 0..1
weakest   = минимальный вес пары                                               // он же гейт режима
strength  = 0.8 * harmony + 0.2 * weakest
structure = композиция, зажата в [-1, 1], выше 0.75 не поднимается
personal  = личные оценки, в [-1, 1]

raw  = strength + 0.12 * structure + 0.15 * personal
балл = round(100 * (raw + 0.27) / 1.36)                // 0..100
```

Пятая часть силы берётся от самой слабой пары: в миксе она заметна целиком, а среднее её размывает.

Среднее берётся по связям банок, а не по парам вкусов: иначе банка с тремя вкусами даёт втрое больше пар
и перетягивает балл на себя. Размах шкалы посчитан из достижимого: структура выше 0.75 не поднимается,
а личные оценки в размах не входят, поэтому сто баллов это идеальный микс по таблицам, и оценки сверх
этого упираются в потолок.

Структура считается по вкусам микса, не по банкам: банка «вишня и мята» даёт один базовый вкус и один
акцентный. Роль банки из следующего раздела нужна только для долей. Акцент: Специи, Травы, Цветы, Растения.
Телом работает любой другой вкус: десертные и гастрономические составы для кальяна такие же рабочие,
как фруктовые, поэтому «сыр и бекон» и «кола и кофе» штрафа не получают.

```
состав из одних акцентов                 -0.5
ровно один акцент                        +0.5
акцентов больше одного                   -0.2 за каждый лишний
разнообразие категорий                   +0.25 * (категорий - 1) / (вкусов - 1)
одна категория на весь состав от трёх    -0.3
```

Личные оценки считаются по попробованным миксам. Для вкуса `f`:
`aff(f) = сумма (оценка - 3) / 2 по миксам с этим вкусом / (число таких миксов + 2)`.
Делитель со сдвигом держит вкус с одной оценкой близко к нулю. Так же считается `affPair(a, b)`
по миксам, где встретились оба вкуса. `personal = 0.6 * среднее aff по вкусам + 0.4 * среднее affPair
по парам, у которых есть данные`. Без данных слагаемое равно нулю. Переключатель в интерфейсе выключает
личные оценки целиком; он включён, когда есть хотя бы один оценённый микс, и спрятан, когда оценок нет.

### Поиск

Банки полки образуют граф: ребро между банками есть, если минимальный вес пары их вкусов проходит гейт режима.
Банки с общим вкусом ребра не получают: микс «вишня и вишня с мятой» смысла не имеет, а запрет в смежности
ещё и срезает ветки перебора.

| Режим | Что показывает |
|---|---|
| Проверенные | все пары зелёные и выше |
| Сбалансированные | все пары описаны, синий и выше |
| Смелые | есть пара без данных, остальные синие и выше |

Смелые это отдельный набор, а не порог пониже. Порог отсекает слабые пары снизу, а на экране
стоят шесть лучших по баллу: лучшие миксы собраны из красных пар и проходят любой порог, поэтому
режим-порог выдачу не менял. Теперь смелые показывают только то, что таблицы не описывают,
и набор отличается целиком.

Миксы из k банок ищутся обходом в глубину по кликам этого графа: кандидаты на следующую банку только
смежные со всеми выбранными, перебор по возрастанию индекса. Ветка отбрасывается, если даже при весе 1.0
у всех оставшихся пар балл не попадёт в текущий топ. На полке из 90 банок худший замер (k = 6, свободный гейт)
занял 574 мс, обычные запросы единицы миллисекунд. Топ держится в 60 записях, k поддерживается от 2 до 6,
интерфейс предлагает от 2 до 5.

Выдача одной полки это 6 карточек, кнопка «Показать ещё» добавляет следующие 6. Цель считается отдельно
для каждого k. Из найденного она собирается так:

1. Отклонённые наборы вкусов выбрасываются. Их число пишется строкой под выдачей вместе с возвратом.
2. Миксы, чей набор вкусов совпадает с попробованным, выбрасываются. Их число пишется строкой под выдачей.
3. Совпадение с запланированным миксом оставляется с пометкой «в планах».
4. При k от трёх кандидат откладывается, если от уже выбранного отличается одной банкой. При k = 2 правило
   не работает: любые две пары либо не пересекаются, либо делят ровно одну банку, и выдача выродилась бы
   в набор непересекающихся пар.
5. Вкус попадает не чаще, чем при равномерной раскладке вкусов полки по странице выдачи: порог равен
   `ceil(6 * банок в миксе / вкусов на полке)`, минимум два. Сыр сочетается с доброй половиной справочника,
   и без этого правила он занимал почти всю выдачу. От числа показанных карточек порог не зависит, поэтому
   «Показать ещё» не перетряхивает уже показанное.

Отложенные кандидаты не выбрасываются. На первой странице они добирают список до трёх карточек, когда разных
миксов не нашлось, а их остаток виден строкой «Ещё N миксов повторяют те же вкусы». По кнопке «Показать ещё»
отложенные показываются с пометкой «повторяет вкусы выше»: страницу повторами не набиваем, но и прятать
их насовсем незачем.

Если карточек меньше трёх, подбор добавляет миксы следующего режима к уже найденным и пересобирает выдачу.
Именно добавляет: смелые это другой набор, и заменять им найденные красные пары нельзя. Считаются карточки,
а не кандидаты, потому что попробованные и скрытые уходят из выдачи уже после перебора. В выдаче пишется,
что режим ослаблен. Если пусто во всех режимах, пользователь видит, сколько банок на полке и каких пар не хватает.

### Число банок и роли

Страница подбора начинается с вопроса «Сколько банок в миксе?» и вариантами 2, 3, 4, 5 и «Неважно».
Ответ запоминается и дальше работает переключателем сверху.

«Неважно» означает, что число выбирает алгоритм: считаются все k от 2 до 5 (5 только при полке от 10 банок),
берётся наибольшее k, у которого лучшая карточка отстаёт от лучшей вообще не больше чем на 5 баллов.
Сравнивается именно лучшая карточка: балл падает с числом пар в миксе, и средние разных k несравнимы, иначе
выбор всегда упирался бы в две банки. Полка из одной-двух карточек выбором не становится, пока есть полка
с нормальной выдачей. Выбранное k раскрыто, остальные показаны свёрнутыми полками.

Роль банки определяется по её вкусам: акцент, если все вкусы из акцентных категорий; основа, если есть
вкус базовой категории; иначе дополнение. Доли считаются из весов роли (основа 1.0, дополнение 0.6,
акцент 0.35), нормируются к сотне и округляются до пяти, остаток идёт первой банке. Две базы дают 50/50,
основа с акцентом 75/25, основа с дополнением и акцентом 50/30/20.

## Интерфейс

Четыре раздела в существующем сегментированном переключателе: Граф, Полка, Подбор, Миксы.
Стили, тёмная тема и мобильная вёрстка берутся из текущих, `styles.css` не переписывается.

### Полка (`#/shelf`)

Сверху выбор вкусов: поиск и список по категориям, тот же, что в фильтрах графа, выносится в общий компонент.
Галочка создаёт банку на один вкус, снятие удаляет банку, если её не правили руками.
Ниже список банок: бренд, название, вкусы чипами, кнопки правки и удаления. В форме банки меняются бренд,
название и набор вкусов. Строка состояния показывает число банок и вкусов.

### Подбор (`#/picks`)

Пустая полка показывает приглашение заполнить полку со ссылкой на раздел.
Дальше вопрос о числе банок, под ним режим риска со значением «Сбалансированные».

Карточка микса:

- Заголовок из названий банок (название на банке или перечисление вкусов).
- Балл и короткая причина («все пары красные», «мята даёт акцент», «вкусы из миксов с оценкой 5»).
- Состав: по строке на банку с долей, ролью, брендом, названием и вкусами.
- Пары вкусов чипами в цвете уровня, серый для пар без данных.
- Пометки: «мало данных», если у вкуса нет своей таблицы; «в планах» при совпадении с планом.
- Кнопки «В планы» (сохраняет сразу), «Попробовал» (открывает форму микса) и значок «Больше не предлагать».

### Миксы (`#/mixes`)

Страница остаётся, форма меняется под новую модель: строка состава это банка с брендом, названием,
вкусами и долей. Вкусы выбираются тем же общим компонентом, произвольный текст сохраняется.
Переход из подбора открывает форму с заполненным составом и долями, оценка и название пустые.

## Проверка

`recommender.ts` чистый модуль без Angular, на него пишутся тесты через vitest (в проекте тестов пока нет,
раннер добавляется в devDependencies). Покрываются: вес пары по уровню, бледная пара не проходит ни один гейт,
балл растёт с уровнем связей, штраф за два акцента, доли дают 100 в сумме, ослабление гейта при пустой выдаче,
исключение попробованного набора, отличие от соседа одной банкой.

Миграция проверяется отдельно: файл версии 1 с текстовыми вкусами загружается, вкусы сопоставляются
со справочником, оценки сохраняются.

Страницы проверяются в браузере на реальных данных: полка из десятка банок, подбор на каждом числе банок,
перенос микса в планы и в попробованные.

## Решения, принятые без обсуждения

- Пары вкусов внутри одной банки не оцениваются.
- Бледные пары не попадают в миксы ни в одном режиме. Бледной считается пара, у которой бледные все ячейки.
- Банки с общим вкусом вместе не предлагаются.
- Структура считается по вкусам, роль банки нужна только для долей.
- В одной полке выдачи 6 карточек, дальше по кнопке.
- Правило «отличается одной банкой» не работает при двух банках в миксе.
- Вкус в полке это каноническое имя из `products.json`, выбор только из справочника.
- Файл версии 1 заменяет миксы и не трогает полку.
- Вопрос в подборе про число банок, не про число вкусов: банка с двумя вкусами даёт микс из двух банок и трёх вкусов.
- Балл показывается числом от 0 до 100, нормировка линейная от минимума и максимума raw.
- Режим риска добавлен сверх запрошенного, потому что на половине вкусов данных мало и без ослабления
  требований выдача пустеет.
- Под переключателем режима стоит строка о том, что режим означает. Проверенные и сбалансированные
  на богатой полке дают одинаковый верх выдачи, и без этой строки переключатель выглядит нерабочим.
- Полка не хранит остаток табака и признак «закончился».
- Граница категорий для ролей: основа это Фрукты, Ягоды, Цитрус; акцент это Специи, Травы, Цветы, Растения.
